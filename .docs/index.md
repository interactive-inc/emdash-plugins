# 設計と開発

## 構成

- Astro + EmDash + React + json-render。EmDash本体はnpm依存として使い、ネイティブプラグインで拡張する。
- `packages/emdash-plugins`は`@interactive-inc/emdash-plugins`として配布する。プラグインは`src/<name>/`に置き、`./<name>`のサブパスで公開する。`apps/web`が利用する。
- `builder`プラグインが検証・部品・MCP拡張・描画・CSS・プレビューを提供する。プラグインIDは`builder`で、widget・MCPスコープ・APIルートの名前空間になる。
- ホストは`builderPlugin()`と`builderIntegration()`を同じ設定で登録する。integrationはEmDashが読み込むプラグインのruntimeを検査付きのものに差し替え、設定が違えば起動時に止める。`builderPlugin()`だけの構成（独自ルートで描画する場合）も保つ。
- 既定の`pages.document`はバージョン付きJSON。保存先・公開URL・プレビューURL・トップページslugは設定可能。独自部品はホストのコードで登録し、MCP・検証・描画で共用する。保存前と描画前に共通カタログで検証する。
- GUIではdocumentの入力欄をプレビューへ置換し、チャット管理のタイトル・説明欄を隠す。公開・履歴・認証はEmDash標準。
- MCPは登録済み部品を組み合わせる。任意のJavaScript・CSS・HTML・fetch先は受け付けない。部品の追加にはコード変更が必要。
- プレビューと公開ページは同じレンダラーを使う。署名は1ページだけを許可し、参照記事の下書きへ権限を広げない。
- ローカルはSQLite・ローカルメディア。本番用に公式Cloudflareアダプター（Workers・D1・R2・KV）を用意する。

## モーション

- json-renderのReactツリーをそのままブラウザーでハイドレーションし、Motion for React（`motion/react`）で再生する。描画フレームワークもページ専用のスクリプトも増やさない。
- バインディング・表示条件・repeatはサーバーの`resolvePage()`で解決し、部品スキーマで再検証して宣言されたフィールドだけを残した表示内容（`ResolvedView`）をislandへ渡す。URLとリッチテキストもここ（`projectPortableText()`）で表示用に確定し、描画側は確認し直さない。段落の中の画像は`<img>`だけで描画し、キャプションを持たせない。1つのspanに付けるリンクも最初の1つだけにし、描画しない段落スタイルは送らない（`<p>`になり、入れ子のリストを段落の中に入れてしまう）。段落の中の`<figure>`もリンクの中のリンクも、ブラウザーが分けてしまい、ハイドレーションが一致しなくなるため。サーバーとブラウザーが同じ値から同じツリーを描画するためハイドレーションの差分が出ず、下書きの他フィールドや表示しないデータはブラウザーに届かない。例外は独自部品が緩いスキーマ（`z.looseObject`・`.catchall()`・`z.record`・`z.unknown`・`z.any`）で宣言したpropで、値はJSONの形（日付はISO文字列、`$`で始まるキーは除く）でそのまま届く。
- モーションのないページはislandを出力しない。JavaScriptなしで、マークアップはモーション導入前と同じ。描画されない要素（安全なsrcのないImage）は表示内容から除くため、その値もモーションもブラウザーに届かない。
- ラッパーを足さず、各部品の一番外側の要素をMotionの要素として描画する。レイアウト・CSSセレクター・アクセシビリティツリーはモーションの有無で変わらない。
- 待機中の要素は、最終的な位置に透明（`opacity:0`）で置く。SSRのstyle属性がこの状態なので、完成状態が見えてから隠れるちらつきが起きない。開始状態の移動・拡大（`transform`）は入場の再生中だけ使う。KVは読み込みのたびに再生する。
- 表示の責任は段階的に持つ。Motionが担当するのは、ハイドレーション後に要素を引き受けた（`data-motion-armed`）後だけ。それまではCSSが1.5秒後に完成状態へ表示する。遅延の値は`site.css`だけが持つ。JavaScript無効・印刷・reduced motion・スクリプトなしの管理画面iframeは、CSSと`<noscript>`で完成状態に固定する。
- 一度見えた要素は隠さない。CSSで表示された後にハイドレーションした場合、画面内・画面より上・画面の下1画面分までの要素はそのまま表示し（フェード中ならCSSが終えるのを待ってからMotionが完成状態を引き受ける）、それより下の要素だけをスクロール時に再生する。位置はハイドレーションのコミット中の座標ではなく、その後のIntersectionObserverの最初の報告（`MotionStage.locate`）で判定する。長いハイドレーションの間も合成スレッドはフリックを続けるため、メインスレッドの座標は古く、判定から表示の反映までにも1〜2フレームかかる。下に1画面分の余裕を取るのはそのため。IntersectionObserverの余白は途中のスクロールコンテナには効かず、コンテナの見えている範囲で切り取られる。そのため、スクロールできるコンテナの中の要素は、いちばん外側のコンテナの位置で判定する（行の外へはみ出したスライドも、スワイプですぐ画面に入りうる）。数えるのは、`overflow`が`auto`か`scroll`の軸で中身が実際にはみ出しているコンテナだけ（`html,body{overflow-x:hidden}`の`<body>`は縦に`auto`でもはみ出さない）。`<html>`の代わりにビューポートがスクロールし、`<html>`がoverflowを持たないときは`<body>`の代わりにもビューポートがスクロールする（`body{overflow-x:hidden}`を含む）ため、この2つはその場合に数えない。ページ全体を独自のコンテナでスクロールさせるレイアウトでは、その中の要素がすべて「近い」になり、遅れたハイドレーションでは入場を再生しない（隠すよりよい）。フォーカスが入った要素は完成状態で表示し、ハイドレーション後はフォーカスが外れても固定する。
- 読み込み時にreduced motionの訪問者とIntersectionObserverのないブラウザーでは、client directive（`client:builder-motion`）がislandを読み込まず、`data-motion-static`でそのページを静的に固定する。途中で設定を戻してもハイドレーションしない。スクロール復元・アンカーで通り過ぎた要素は再生せずに表示し、スクロール位置を動かさない。
- 入場は`MotionStage`が判定する。要素は最終的な位置で待つため、見えるかどうかはブラウザーのIntersectionObserverがそのまま判定する。`.site`・カード・横スクロールの行・閉じたアコーディオンや`<details>`など、要素を切り取るコンテナの中では見えるまで待ち、開いたりスクロールしたりして見えた時点で再生する。面積のない要素は、端に触れただけで全体が見えた扱いになる。読み込み中の画像は画素がなく高さも0になりやすいため、`decode()`が終わってから監視を始める（空の枠で再生してから写真が出ることも防ぐ）。ほかの面積のない要素は、はみ出した中身を隠したままにしないよう、触れた時点で判定する。もう1つのIntersectionObserverは`rootMargin`で画面より上全体を見て、そこに見えている要素を通り過ぎた要素として再生せずに表示する。固定配置（`position: fixed`）の中の要素はスクロールで戻らないため、通り過ぎた扱いにしない。WebKitはレンダリング更新の中でしかIntersectionObserverを更新せず、合成スレッドのアニメーションはレンダリング更新を起こさない。そのため、マーキーなどに運ばれて画面に入った待機中の要素や、スライドする窓（`overflow`で切り取る祖先）から見えてくる要素が、見えないまま残りうる。待機中の要素がある間は250msごとに2つを確かめ、どちらかならフレームを要求する。1つは、待機中の要素の祖先が自身のアニメーション（`getAnimations()`。疑似要素のものは子を運ばないので含めない）を再生中か。数えるのは時間で進むアニメーション（`DocumentTimeline`）だけ。スクロール駆動のアニメーションは止まったページでも`running`のままだが、スクロール中しか動かず、スクロールはWebKitでもレンダリング更新を起こす。窓だけが動いて中身が止まっている場合はこれで分かる。もう1つは、各要素の`getBoundingClientRect()`が前回から動いたか。合成スレッドのアニメーションで運ばれた位置もここに反映され（WebKitでも描画の更新なしで読める）、closedのシャドウルートの中のアニメーションのように、どのAPIからも見えない運び手も分かる。イベントは待たない。一時停止からの再開やWeb Animations APIでの開始はイベントを出さない。毎回フレームを要求する方法は取らない。WebKitではアイドル中もコア1本の約1%を使い続ける。祖先の確認は、どの要素も動いていないときだけ行う。待機中の要素の祖先で終わらないアニメーション（パルスなど）が動いている間は、要素が動かなくてもフレームを要求し続ける（WebKitでは毎回要求する方法と同程度）。アニメーションの再生中に位置を読むと、Chromeではスタイルの再計算が1回増える（アニメーション20個でコア1本の0.3〜0.5%ほど）。どちらの確認も座標で表示を決めるものではなく、判定は常にIntersectionObserverが行う。また、読み込み中（`readyState`が`complete`になる前）のWebKitは、新しく監視を始めた要素の最初の報告を、レンダリング更新が起きるまで最大2秒ほど遅らせる。そのため監視を始めるたび（`decode()`を待った画像も含む）と`locate()`のたびに、フレームを1回だけ要求する。固定配置とスクロールコンテナの判定は、ブラウザーが描画するツリー（割り当てられたslotを通り、シャドウルートからホストへ出る）で祖先をたどる。closedのシャドウルートはslotを外に見せないため、その中身はホストから先をたどる。`<html>`の上の`document`は`ShadowRoot`ではないので、`host`を読まない（`<form name="host">`などがあると、その要素が返る）。切り取りをJavaScriptの座標計算やスクロールの監視で再現しない（スクロールバー・`contain`・`clip-path`などで判定がずれる）。Motionは再生だけを担う。再生中の移動がスクロール領域を広げないよう、`.site`は`overflow: clip`にし、`.site`より内側のスクロールコンテナの中では入場で移動も拡大縮小もせず、フェードだけを再生する（縮小はスクロールスナップの位置を動かす）。スクロールコンテナとして数えるのは、`overflow`が`auto`か`scroll`のコンテナ（今ははみ出していなくても、画面幅で変わる）と、`overflow: hidden`でスクロールスナップを持つコンテナ（ボタンで送るカルーセル）。`overflow: clip`はスクロールコンテナではなく、スナップも効かない。角丸を切り取るだけの`overflow: hidden`のカードは何もスクロールしないので、中の要素は移動して入場する。Motionはレンダーのたびにvariantを解決し直すため、フェードだけにするかどうかは入場の開始時に1度だけ決める（決め直すと、表示済みの要素が再びスライドする）。Sectionは全幅の帯とアンカー先なので動かさず、動く要素の中にも置かない。
- 値はトークンだけ。秒数・距離・イージングはパッケージで固定し、MCPから任意のアニメーション・CSS・スクリプトは指定できない。
- 独自部品は`motion: true`と`Root`で同じ仕組みに参加し、Motionを直接importしない。`motion: false`では注入ルートが`virtual:emdash-plugins/builder/page-shell`でislandを含まない`StaticPageShell.astro`を使うため、islandをビルドせず、独自部品もブラウザーへ配信しない。

## 開発

[起動・検査](../README.md) · [MCPとページの操作](../apps/web/README.md) · [パッケージAPI](../packages/emdash-plugins/README.md) · [デプロイ](deployment.md)

- コマンドはVite+（vp）を使う。PortlessのURLは`https://emdash-plugins.localhost`。
- 依存・設定・環境・プラグインのビルドを変える前に開発アプリを停止し、変更後に完全に起動し直す。EmDash 1.3.1は内部再起動後に古いVite runnerを参照する場合がある。
- `vp run check`、`vp run test`、`vp run build`で型・ユニット・SSR・ビルドを検査する。
- `vp run test:package`は一時フォルダーの独立ホストでインストール・MCP・公開/下書き・プレビューを検査する。配布ファイルはリポジトリへ残さない。
- `vp run smoke`は起動中のローカルアプリ専用。公式開発ログインを使うため本番へ実行しない。
- ライセンスはMIT。npmへの公開は`packages/emdash-plugins`で`vp pm publish`を実行する。
