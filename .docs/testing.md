# 検査の分担

普段の変更にはビルド不要のテストを使い、リリースの判断には実EmDashと配布物の検査を使う。軽いテストの成功だけで配布可能とは判断しない。

## 開発中

- `vp run test`: `tests/<plugin>/*.test.ts`と`*.test.tsx`をソースから実行する。DB・HTTP・ビルド済みファイルは不要。
- 小さな変更では`vp run test -- tests/builder/document.test.ts`のように対象ファイルを指定する。パスは`packages/emdash-plugins`からの相対パスで、複数指定できる。AIは変更箇所と呼出元・利用側に応じて対象を選ぶ。共通処理の変更では引数なしで全件を実行する。CIも常に全件を実行する。
- テスト結果のキャッシュや常駐プロセスは使わない。実行のたびに指定した検査を実際に行い、ファイルごとのプロセス隔離を保つ。
- `vp run verify`: パッケージの型検査と普段のテスト。サンプルのAstro型検査やビルドは含めない。
- モックはEmDashの読取・署名境界とブラウザーの通信だけに置く。検証・解決・描画・プラグインの権限判断は実装を実行する。モジュールモックはファイルごとのプロセスで隔離し、ケースごとに呼出履歴と実装を戻す。
- 読取失敗を404や成功と混同しないこと、不正な保存データから追加のコンテンツを取得しないこと、データ取得失敗で不完全なページを返さないこと、表示しないフィールドをブラウザー向けのviewへ渡さないことを確認する。

## 結合とリリース

- `vp run test:integration`: `tests/<plugin>/integration/*.test.ts`と`*.test.tsx`を実行する。実EmDashの署名、有効期間、プラグイン設定の一致、jsdomでのSSRとハイドレーション、サンプルの配布パッケージ利用を確認する。
- `vp run test:all`: 普段のテストと結合テストを両方実行する。既存テストを削って高速化しない。
- `vp run release`: 全型検査、全テスト、Node/Cloudflareビルド、`test:package`を順に実行する。途中で失敗したら止まる。公開やデプロイはしない。
- `test:package`は実際の配布物を一時ホストへ導入し、MCP・標準の公開と下書き・プレビュー・ロール別権限・独自設定・モーション無効時の静的出力・islandのJavaScript容量を確認する。
- 一時ホストの開発サーバーは検査プロセスが直接起動・停止する。バックグラウンド起動コマンドの固定30秒制限は使わず、最大180秒のHTTP待機とプロセスの終了検知を行う。初回のSSRにはコンパイルも含まれるため、1回のHTTP待機は残り時間を上限に最大30秒とする。失敗時も子プロセスを停止する。ログは表示された一時フォルダーの`test-dev.log`に残す。
- ビルドを伴う検査の前は開発アプリを停止し、完了後は新しいプロセスで起動する。`test`だけなら停止は不要。
- `vp run smoke`は起動中のローカル開発サーバー専用。ローカルの署名キーとDBが必要なので、リリースの一括コマンドには入れない。公開前にローカルの操作を追加確認するときに使う。

## CI

- `CI`: PRとmainへのpushでパッケージ型検査と普段のテストを実行する。PRの更新では古い実行を取り消す。作業ブランチへのpushとPRで二重に実行しない。
- `Release checks`: 手動実行または`v*`タグへのpushで`release`を実行する。公開・デプロイ前に、その対象コミットで成功したことを確認する。タグ名やワークフローの成功だけではnpmへ公開されない。
- 既存の`verify`ジョブ名を維持する。GitHubのブランチ保護・必須チェック設定は変更しない。

## 検証できない範囲

- モックはEmDash本体の認可実装やDBの公開状態を保証しない。実EmDash・HTTP経由の検査をリリース前に残す。
- jsdomはレイアウトを持たず、IntersectionObserverと座標はテストが与える。Safari・Chromeなどの実際の描画、スクロール、合成処理、WebKitの挙動はこの自動検査の対象外。実ブラウザーでの検証は別途必要。
- Cloudflareビルドの成功は実Workers・D1・R2・KVでの動作確認を意味しない。デプロイ後の確認は[デプロイ手順](deployment.md)に従う。
